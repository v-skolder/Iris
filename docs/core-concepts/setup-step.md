# Setup step

Iris owns one runtime configuration object at `app.config`. The desktop app collects any `SetupField` values into that configuration and passes it to `SetupStep.configure(config)`. Iris applies the returned values to that same object, preserving its identity. Setup steps validate the environment and add values needed by later operations. The Cube and the selected Publisher receive this same configuration object when their operations run, after setup has completed successfully.

The [example implementation](../../project-example/src/setup_steps/example_setup_step.py) checks `drive_path` and verifies Databricks authentication. It returns values including the validated path and a `generate_token` callable. A remote Cube calls `config["generate_token"]()` when it needs a token in `get_data(partitions, config)` or `list_partitions(config)`. In the example, the `DirectoryPublisher` path callable runs only when publishing and reads `config["drive_path"]`. That argument is the same object as `app.config`, which setup has already populated; registering the publisher does not resolve its path early.

The returned configuration is runtime state in the desktop process. Credentials and tokens must not be logged, written to the SQLite data cache, passed to dashboard HTML, or included in published artifacts. The Databricks CLI handles token refresh when the callable requests a token. If interactive login is required again, the failed operation must trigger the setup flow rather than exposing the token error to the HTML.
